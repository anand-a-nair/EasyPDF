# Sustainability

Free to users. Never free to build. This file exists because the most common
death for an ambitious open source project is not technical failure — it's the
maintainer getting a demanding job and the commits stopping.

## The VLC model

VLC is the closest precedent to what EasyPDF wants to be, so it's worth being
precise about how it survived. **VideoLAN** is a nonprofit association with
institutional roots at École Centrale Paris. **VideoLabs** is a separate
commercial company doing consulting and contract work, and it employs core
developers.

The application is free. The engineering is funded. Those are not in conflict,
and the second is what made the first durable for two decades.

## Options compatible with staying free and Apache-2.0

**Consulting and contract work** — the VideoLabs model. Companies pay for
integration, custom features, and expertise; the tool stays free. Strongest
option, and the only one on this list with a twenty-year proof.

**Public-interest grants** — [NLnet](https://nlnet.nl) and Germany's
[Sovereign Tech Fund](https://www.sovereign.tech) fund exactly this category:
local-first, privacy-preserving infrastructure with a digital-sovereignty
argument. A no-cloud document tool that reduces dependence on a single US vendor
is squarely within their stated mandate. This is realistic money, not a lottery
ticket.

**Enterprise support contracts** — the software stays free; organizations pay
for an SLA, deployment help, and someone to call. Doesn't compromise the free
tool at all, and it's the thing enterprises actually need in order to adopt.

**Donations and sponsorship** — GitHub Sponsors, Open Collective. Real, but
rarely sufficient alone. Treat as supplementary.

## Closed doors, deliberately

Apache-2.0 with **no CLA** means contributors retain their copyright. That makes
later **dual-licensing or an open-core pivot effectively impossible** without
tracking down every contributor for permission.

This is the right call for the project described in
[01-vision.md](01-vision.md) — it's a credible, permanent guarantee that the
tool cannot be taken proprietary, which is precisely the promise Adobe can't
make. But it is a decision, not an accident, and it should stay a decision made
knowingly. Revisiting it later is expensive and gets more expensive with every
contributor. See OQ-006.

## Timing

Set up the legal and funding structure — fiscal host or nonprofit, and a first
grant application — **while enthusiasm is high**. Not when burnout has already
started, which is when it's most needed and least likely to happen.

## Honest scale check

Adobe has hundreds of engineers on Acrobat. This project will not out-execute
that on feature breadth, and shouldn't try. It can win by being faster, more
trustworthy, and free — which is a different axis and one Adobe structurally
cannot compete on. See [10-strategy.md](10-strategy.md).
